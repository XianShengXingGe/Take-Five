# 片刻（Take Five）产品需求文档（PRD）

版本：MVP v1.0\
产品名称： - 中文：片刻 - English：Take Five

------------------------------------------------------------------------

# 1. 产品概述

## 1.1 产品定位

片刻（Take Five）是一款面向 Coding Agent 用户的智能通知工具。

它解决的问题：

> 用户启动 AI Agent 执行开发任务后，不需要持续盯着电脑等待。当 Agent
> 完成任务、需要用户输入、等待授权或异常停止时，通过手机通知主动提醒用户。

核心理念：

> 让 AI 工作，用户获得片刻自由。

------------------------------------------------------------------------

# 2. 用户使用场景

## 场景 1：等待 AI 完成长任务

用户：

-   启动 Codex / Claude Code / OpenCode / Antigravity；
-   分配一个开发任务；
-   离开电脑去休息、吃饭、运动。

问题：

-   不知道 AI 什么时候完成；
-   需要频繁查看电脑状态。

片刻解决：

-   Agent 完成任务后发送通知；
-   用户收到提醒后回来检查结果。

------------------------------------------------------------------------

## 场景 2：Agent 等待用户决策

用户：

-   让 AI 重构代码；
-   AI 遇到设计选择问题。

问题：

-   AI 停在那里等待；
-   用户不知道任务已经暂停。

片刻解决：

-   通知用户"等待输入"；
-   用户回来继续处理。

------------------------------------------------------------------------

## 场景 3：Agent 等待权限

用户：

-   AI 需要执行安装依赖、执行命令等操作。

问题：

-   AI 因权限确认停止；
-   用户离开电脑后任务无法继续。

片刻解决：

-   通知用户"等待授权"。

------------------------------------------------------------------------

## 场景 4：Agent 异常停止

用户：

-   启动长时间任务后离开。

问题：

-   API 错误；
-   Agent 崩溃；
-   达到执行限制。

片刻解决：

-   主动提醒用户处理异常。

------------------------------------------------------------------------

# 3. 用户价值

## 核心价值

从：

> 人等待 AI

变成：

> AI 主动通知人。

------------------------------------------------------------------------

## 用户收益

### 降低等待焦虑

用户无需持续查看：

-   Terminal；
-   IDE；
-   Agent 窗口。

------------------------------------------------------------------------

### 提高 AI 使用效率

减少：

-   AI 已完成但用户不知道；
-   AI 等待输入但用户没发现；
-   AI 异常停止无人处理。

------------------------------------------------------------------------

### 支持多 Agent 工作流

用户可以同时运行：

-   Codex；
-   Claude Code；
-   OpenCode；
-   Antigravity。

通过通知图标快速区分来源。

------------------------------------------------------------------------

# 4. 产品形态

## 4.1 软件形式

片刻不是单独的 Agent 插件。

交付形式：

> 一个独立跨平台软件 + 自动安装的 Agent Adapter。

用户安装：

``` bash
takefive install
```

即可。

------------------------------------------------------------------------

## 4.2 支持平台

MVP：

-   macOS
-   Windows

暂不支持 Linux。

------------------------------------------------------------------------

## 4.3 支持 Agent

MVP 支持：

-   Codex
-   Claude Code
-   OpenCode
-   Antigravity

------------------------------------------------------------------------

# 5. 产品架构

整体结构：

                    Take Five

                  Notification Core

                        |

                     Bark API

                        |

                     手机通知


                        ↑

         --------------------------------

         Codex Adapter
         Claude Adapter
         OpenCode Adapter
         Antigravity Adapter

设计原则：

1.  用户只安装一次；
2.  Bark 只配置一次；
3.  所有 Agent 共用通知规则；
4.  Adapter 只负责事件转换；
5.  Core 负责通知逻辑。

------------------------------------------------------------------------

# 6. 首次安装流程

## Step 1：安装

用户执行：

``` bash
takefive install
```

自动进入初始化。

------------------------------------------------------------------------

## Step 2：检测 Agent

显示：

    检测 Coding Agent

    ✓ Codex
    ✓ Claude Code
    ✓ OpenCode
    - Antigravity 未检测

检测到的 Agent 默认启用。

------------------------------------------------------------------------

## Step 3：配置 Bark

用户输入：

    Bark 推送地址

支持：

-   Bark 官方服务器；
-   自建 Bark Server。

------------------------------------------------------------------------

## Step 4：测试通知

发送测试：

    片刻

    连接成功

    通知配置完成。

------------------------------------------------------------------------

## Step 5：确认通知规则

默认：

  状态       开关   等级
  ---------- ------ ----------
  任务完成   开启   普通提醒
  等待输入   开启   重要提醒
  等待授权   开启   重要提醒
  异常停止   开启   重要提醒

------------------------------------------------------------------------

## Step 6：安装 Adapter

自动配置：

-   Codex Hook；
-   Claude Hook；
-   OpenCode Plugin；
-   Antigravity Hook。

------------------------------------------------------------------------

# 7. 通知事件定义

统一内部事件：

## task_completed

含义：

Agent 正常完成当前任务。

默认：

-   开启；
-   普通提醒。

------------------------------------------------------------------------

## waiting_input

含义：

Agent 需要用户回答问题才能继续。

默认：

-   开启；
-   重要提醒。

------------------------------------------------------------------------

## waiting_permission

含义：

Agent 等待用户授权。

默认：

-   开启；
-   重要提醒。

------------------------------------------------------------------------

## task_failed

含义：

Agent 无法继续执行。

例如：

-   API 错误；
-   Session 异常；
-   达到执行限制。

默认：

-   开启；
-   重要提醒。

------------------------------------------------------------------------

# 8. 通知等级设计

用户界面不要显示 Bark 技术参数。

显示：

## 静默通知

说明：

只进入通知中心，不主动提醒。

对应：

passive

------------------------------------------------------------------------

## 普通提醒

说明：

像普通 App 通知一样提醒。

对应：

active

------------------------------------------------------------------------

## 重要提醒

说明：

专注模式下也尽量提醒。

对应：

timeSensitive

------------------------------------------------------------------------

## 强提醒

说明：

静音和勿扰模式下也会提醒。

对应：

critical

------------------------------------------------------------------------

# 11. 自定义通知内容

用户可以修改：

-   Title；
-   Body。

------------------------------------------------------------------------

## Title 限制

-   1\~12 个字符；
-   不允许为空。

------------------------------------------------------------------------

## Body 限制

-   0\~32 个字符；
-   可以为空。

------------------------------------------------------------------------

## Emoji

固定：

-   不允许修改。

原因：

保持状态统一识别。

------------------------------------------------------------------------

## Subtitle

自动生成：

    Agent Name · Project Name

不支持用户修改。

------------------------------------------------------------------------

# 17. 开发原则

## Adapter 必须轻量

Adapter 只负责：

    Agent Event
        ↓
    统一事件

不负责：

-   Bark；
-   配置；
-   通知等级。

------------------------------------------------------------------------

## Core 负责全部业务

包括：

-   状态判断；
-   通知规则；
-   文案；
-   图标；
-   Bark 调用。

------------------------------------------------------------------------

## 配置修改必须安全

要求：

-   增量修改；
-   自动备份；
-   幂等安装；
-   不覆盖用户已有配置。

------------------------------------------------------------------------

# 18. MVP 明确不做

暂不支持：

-   手机回复 Agent；
-   远程控制电脑；
-   查看代码 Diff；
-   查看完整 Agent 输出；
-   AI 自动总结任务结果；
-   多用户同步；
-   云端账号系统。
